ctx · ryggsekken

Fem ting å ta med seg

  1. Cookien er hukommelsen.HTTP er tilstandsløs. Serveren husker ingenting mellom to forespørsler. Det er nettleseren som sender session=2 hver gang.
  2. Ryggsekken lever én forespørsel.setUser fyller ctx.user på nytt hver gang, fra cookien og databasen. Når svaret er sendt, er sekken borte.
  3. Interruptors stopper tidlig.requireUser svarer 401 før controlleren kjører. requireUserPage sender til /login.
  4. Mellom lagene er det funksjonskall.Bare ruter og controller kjenner HTTP. Service og repository tar imot og gir tilbake vanlige verdier, i formen { ok, data } eller { ok: false, error }.
  5. Eieren settes av serveren.ownerId: user.id kommer fra ryggsekken, aldri fra bodyen.
Koden følger mønstrene i webapp/tasks, med prosjekter i stedet for oppgaver. Innloggingen er jukseinnloggingen derfra: ingen passord, og cookien er bare bruker-id-en. Mer om hvert lag står i Fra request til database.
